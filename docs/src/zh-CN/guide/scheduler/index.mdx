# 调度器概览

调度器是你的应用用来创建卡片、安排复习的对象。通常不必从头构建：`defineScheduler({ model, chrono })` 把两部分组合成可复用的定义，而 `DefaultScheduler` 是基于同一套机制做好的预设。各部分如何拼装见[整体架构](../architecture)；每个部件的详细说明见[模型](../model)、[Chrono](../chrono) 与[中间件](../middleware)。

## 定义与实例

调度器存在于两个阶段：

| 阶段 | 是什么 | 如何获得 |
| --- | --- | --- |
| 定义 | 纯 schema 描述：一个模型、一个 chrono，以及可选的中间件。不持有配置，也不持有卡片数据。 | `defineScheduler({ model, chrono })` 与 `.use(...)` |
| 实例 | 绑定到一份已校验配置、可工作的调度器。 | `definition.create({ config })` |

`defineScheduler` 保留具体的模型与 chrono 类型，因此 schema 与处理函数在贯穿 `.use(...)` 时始终有类型检查。`.use(middlewareA, middlewareB)` 返回加入这些中间件（按序）的新定义；原定义不变，仍可复用。调用 `.create({ config })` 会按组合出的 schema 校验该配置，并返回状态独立、互不共享的调度器实例。

:::note 保留定义，按需创建实例
把包含所组合中间件的定义保留在程序层级。当某用户或集合的配置就绪时再调用 `.create({ config })`。每次调用都会校验配置并返回独立实例，因此两次 `.create()` 不会共享调度状态。
:::

## 现成预设

`DefaultScheduler` 是异步工厂，用同样的「定义与实例」机制组装出默认 FSRS-6 模型、`dateChrono` 与标准调度策略的调度器，你只需传入选项。选项与版本见[DefaultScheduler](./default-scheduler)；想先跑起来见[快速开始](../quick-start)。
