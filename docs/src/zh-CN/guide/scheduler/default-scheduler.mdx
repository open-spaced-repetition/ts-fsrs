# DefaultScheduler

`DefaultScheduler` 是异步工厂，返回一个可直接使用的调度器实例。它把模型（默认 FSRS-7）与 `dateChrono` 以及标准调度策略组合在一起，因此你只需配置它的选项。内部它与自定义 `defineScheduler` 使用同一套「定义与实例」机制——预设只是把各部分装配起来的便捷方式。

## 选项

从 FSRS-3~6 升级到 FSRS-7 时，省略 `weights` 以使用 FSRS-7 默认权重，或提供为 FSRS-7 训练的权重。重放历史用于重建卡片状态，不会转换旧版权重。

FSRS-7 卡片除 `stability` 和 `difficulty` 外还包含 `stabilityFast`。旧版 FSRS-3~6 的记忆状态需要通过 `Reschedule` 重放复习历史来重建；参数迁移不会迁移卡片状态，不应以 `0.8 * stability` 推测演化后的快速轨迹。预设为 FSRS-7 启用小数天数；`enableShortTerm: false` 仅关闭显式学习步骤，不会关闭模型的快速轨迹。

需要成本自适应保留率时，自行组合定义，用 `schedulerCostAdrMiddleware` 替换 `schedulerDesiredRetentionMiddleware`。Cost ADR 不是 `DefaultScheduler` 选项。

`scheduler.nextInterval(memoryState, desiredRetention, { card, grade, elapsedDays })` 查询已计算的评分后状态所对应的间隔，只执行 `handlers.nextInterval`，不推进卡片或 chrono；共享间隔策略应放在这个钩子中。

| 选项 | 默认 | 用途 |
| --- | --- | --- |
| `version` | `'FSRS-7'` | 选择 FSRS 模型：`'FSRS-3'`、`'FSRS-4'`、`'FSRS-4.5'`、`'FSRS-5'`, `'FSRS-6'` 或 `'FSRS-7'`。FSRS-7 无法迁移旧版 FSRS-3~6 的权重。 |
| `weights` | 预设权重 | 可选的训练权重；省略时使用所选版本的预设默认值。FSRS-7 需要恰好 34 个 FSRS-7 权重；传入旧版权重会在构造调度器时抛出异常。 |
| `desiredRetention` | `0.9` | 在计算间隔前应用的目标保留率。 |
| `enableShortTerm` | `true` | 启用学习与再学习步骤。 |
| `learningSteps` | FSRS-7: `[]`; 其他版本: `['1m', '10m']` | `enableShortTerm` 开启时应用的学习步骤。 |
| `relearningSteps` | FSRS-7: `[]`; 其他版本: `['10m']` | `enableShortTerm` 开启时应用的再学习步骤。 |
| `enableFuzz` | `false` | 开启时分散间隔以增加变化。 |
| `maximumInterval` | `36500` | 间隔的天数上限。 |
| `clearStatsOnForget` | `true` | `forget` 是否清空 `reps` 与 `lapses`。 |

`DefaultScheduler` 始终使用 `dateChrono`，并按[中间件](../middleware/built-in)页面所述的顺序组合标准策略：目标保留率、模糊间隔、统计、scheduled days、学习步骤、最大间隔、单调间隔。选择 `version` 只改变模型及其参数，不改变这套策略。

该工厂是异步的，使用返回的实例前要先 `await DefaultScheduler(...)`。示例把常用默认值写得很明确：`version`、`desiredRetention`、学习与再学习步骤、模糊间隔和 `maximumInterval`。省略 `weights` 即用所选 FSRS 版本的预设。

## 预设还是自定义定义

当默认的 FSRS 模型、`dateChrono` 与标准策略集契合你的产品时，用 `DefaultScheduler`——这是最快且正确的起点。当需要不同的模型或 chrono、增减策略，或需要为每个用户校验配置时，用 `defineScheduler`。二者最终都落到同一套调度器实例 API（`newCard`、`review`、`rollback`、`preview` 与 `forget`）。定义与实例模型见[调度器概览](./index)。
