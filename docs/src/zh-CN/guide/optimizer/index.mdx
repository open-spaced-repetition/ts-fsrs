# 训练器概览

FSRS 自带默认模型权重，但你可以用自己产品的复习日志重新训练它们，让间隔更贴合所服务的用户。训练器（Optimizer）运行在 `@open-spaced-repetition/binding` 之上：把复习日志 CSV 转成训练项、估算参数，并报告结果对留出复习的预测质量。训练出的权重通过 `weights` 直接喂回 `DefaultScheduler` 或自定义 `defineScheduler`。权重的含义见[模型](../model)，权重的使用位置见[调度器](../scheduler)。

:::warning 注意
Optimizer 目前仍处于 beta 阶段，API 方法可能随时调整。
:::

## 一个包，两种运行时

原生构建与 WASI 构建提供同一套 API。主包在 Node 中优先选择可用的原生模块，浏览器入口使用多线程的 WASI 包。按需安装对应包：

原生模块（Node、服务器与 CLI）：

<PackageManagerTabs command="install @open-spaced-repetition/binding" />

单线程 WASI Preview 1（`wasm32-wasip1`）：

<PackageManagerTabs command="install @open-spaced-repetition/binding-wasm32-wasip1" />

多线程 WASI Preview 1（`wasm32-wasip1-threads`，发布包名使用 `wasm32-wasi`）：

<PackageManagerTabs command="install @open-spaced-repetition/binding-wasm32-wasi" />

多线程构建已弃用，本次发布仍保留，计划在下一版本移除。新的 WASI 集成请使用上面的单线程包。

```ts
import { computeParameters } from '@open-spaced-repetition/binding'
```

要明确选择单线程 WASI，请从 `@open-spaced-repetition/binding-wasm32-wasip1` 导入。两个 WASI 包都可以在 Node 或浏览器 Worker 中运行。

:::note COOP/COEP 与多线程
单线程构建不需要 Cross-Origin-Opener-Policy 或 Cross-Origin-Embedder-Policy 响应头。多线程构建仍要求页面通过 COOP 与 COEP 响应头启用 `crossOriginIsolated`。多线程描述的是运行时能力，不代表训练会自动在后台执行。

`computeParameters` 和 `evaluateWithTimeSeriesSplits` 在所有构建中都返回 Promise。原生 binding 通过后台任务执行；两个 WASI Preview 1 目标（`wasm32-wasip1` 和 `wasm32-wasip1-threads`）都在调用线程中同步计算，再将结果包装成 Promise。浏览器中应从专用 Worker 调用，避免阻塞页面；Worker 可以在进度回调中通过 `postMessage` 向页面发送进度。
:::

## 复习日志流程

训练由几个 binding 调用组成一条短流程：

1. `convertCsvToFsrsItems` 把复习日志 CSV 转成一组 `FSRSItem`。
2. `computeParameters` 根据这些项训练权重并返回权重数组。
3. `evaluateWithTimeSeriesSplits` 衡量这些参数对留出复习的预测质量。

你还可以用 `computeOptimalSteps` 让 binding 推荐学习与再学习步骤。逐个调用见[训练与评估](./train-evaluate)；想跑一次真实训练，用[Playground](../../playground)页的训练器。
