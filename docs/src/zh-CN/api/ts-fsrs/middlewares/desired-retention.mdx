# DesiredRetention

`ts-fsrs/middlewares` 导出 `schedulerDesiredRetentionMiddleware`：

```ts
import { schedulerDesiredRetentionMiddleware } from 'ts-fsrs/middlewares'
```

它为调度器配置贡献 `desiredRetention`，并在模型计算间隔前应用它，因此较低的保留率会产生更长的间隔。

```ts twoslash file="../../../../snippets/run-code/api/ts-fsrs/middlewares/desired-retention.ts"
```

<RunCode code={desiredRetentionCode} />

分别在 `0.9` 与 `0.8` 保留率下运行同一次复习，到期时间会相差六天，而稳定性保持不变。

**另见** —— [内置策略](../../../guide/middleware/built-in)。

`desiredRetention` 接受 `(0, 1)` 内的有限数字，或以默认 FSRS 四种评分为键的记录。自定义评分方案请使用 `createSchedulerDesiredRetentionMiddleware(scale)`，返回的中间件的 `desiredRetention` 配置项接受 `(0, 1)` 内的有限数字，或以该评分方案的非手动评分为键的记录。`nextInterval` 处理函数写入候选保留率映射；独立查询显式传入的保留率优先。

Cost ADR 针对默认 FSRS 评分方案，根据记忆状态和复习成本调整保留率。组合时用 `schedulerCostAdrMiddleware` 替换 `schedulerDesiredRetentionMiddleware`；它不包含在 `DefaultScheduler` 中。间隔上限仍由 `schedulerMaximumIntervalMiddleware` 负责。
