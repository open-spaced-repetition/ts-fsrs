# ミドルウェア概要

ミドルウェアは、スケジューラにスケジューリングのポリシーやアプリケーション固有のフィールドを追加します。モデルが記憶状態と間隔を計算し、chrono のプリセットがその間隔を期限に変換します。ミドルウェアはその間に位置し、目標保持率や間隔の調整、学習ステップの管理、モデルが扱わないカードの追加データの更新を担います。各部分の役割は[アーキテクチャ](../architecture)を参照してください。

:::note ミドルウェアの境界
スケジューラはモデル・chrono・ミドルウェアを組み合わせます。モデルは記憶状態の更新と間隔計算に限定し、chrono は時間値と日数演算を担います。ミドルウェアはコア操作の前に入力を提供し、その後に結果を調整し、両者が定義しないフィールドを保持します。
:::

## フィールドと処理を定義する

`Middleware` の定義には必須の `name` と、任意のスキーマ、デフォルト値、ハンドラがあります。`defineMiddleware()` はスキーマからハンドラ内の型を推論します。`ts-fsrs` からインポートでき、組み込みポリシーは `ts-fsrs/middlewares` からも利用できます。

| 定義 | 用途 |
| --- | --- |
| `schema.config` | `create({ config })` に渡す設定を検証します。ミドルウェアはスケジューラの設定オブジェクトを共有します。 |
| `schema.card` | 入出力カードのフィールドを宣言し、検証します。 |
| `schema.revlog` | ロールバックに必要な値を含め、復習ログのフィールドを宣言し、検証します。 |
| `schema.cardInitInput` | カード ID など、`newCard()` が受け取る追加の入力を宣言します。 |
| `defaultValue.card` | カードの作成時とリセット時にフィールドの値を設定します。`ctx.operation` で操作を区別できます。 |
| `handlers.review` / `handlers.rollback` | 次のハンドラを呼び出す前後で `ctx.result` を更新します。実行方法は[ライフサイクル](./lifecycle)を参照してください。 |

スキーマは実行時の検証と TypeScript の型推論の両方に使われます。以下の例では Standard Schema に対応した Zod を使います。アプリケーションで実行するには、ts-fsrs に加えてインストールしてください。

## 取り消し可能な連続正解カウンタを追加する

この例では、Again 以外の評価で `streak` を増やし、上限を `streakLimit` とします。Again ではゼロに戻します。復習ハンドラで変更前のカウンタを revlog に保存するため、リセット後に取り消しても元の値を復元できます。

カウンタは `0` から `1` に増え、Again で `0` に戻り、ロールバックで `1` に復元されます。プレビューでは Again、Hard、Good、Easy の順に `0, 2, 2, 2` となり、入力カードのカウンタは `1` のままです。

`base.use(streakMiddleware)` は新しいスケジューラ定義を返し、元の `base` は変更しません。戻り値を保持するか、例のように続けて `.create()` を呼び出してください。ミドルウェアは `use` で組み合わせるため、ハンドラはスケジューラのコアを囲んで一定の順序で実行されます——詳細は[ライフサイクル](./lifecycle)を参照してください。

既成のポリシーは一般的なケースをカバーし、`DefaultScheduler` は既にそれらを組み合わせています。[組み込みポリシー](./built-in) を参照するか、既成のスケジューラを使う場合は[クイックスタート](../quick-start)を参照してください。
