# スケジューラ概要

スケジューラは、アプリケーションがカードを作成し復習を予定するために呼ぶオブジェクトです。通常はゼロから組み立てることはありません。`defineScheduler({ model, chrono })` が二つの部品を再利用可能な定義に組み合わせ、`DefaultScheduler` は同じ仕組みから作られた既製のプリセットです。各部分の関係は[アーキテクチャ](../architecture)、各要素の詳細は[モデル](../model)、[Chrono](../chrono)、[ミドルウェア](../middleware) を参照してください。

## 定義とインスタンス

スケジューラには二つの段階があります。

| 段階 | 内容 | 得る方法 |
| --- | --- | --- |
| 定義 | schema だけの記述。モデル・chrono・任意のミドルウェアで構成され、設定もカードデータも持ちません。 | `defineScheduler({ model, chrono })` と `.use(...)` |
| インスタンス | 検証済みの一つの設定に束縛された、動作するスケジューラ。 | `definition.create({ config })` |

`defineScheduler` は具体的なモデルと chrono の型を保持するため、`.use(...)` を通しても schema とハンドラの型検査は保たれます。`.use(middlewareA, middlewareB)` はそれらのミドルウェアを順に加えた新しい定義を返し、元の定義は変わらず再利用できます。`.create({ config })` を呼ぶと、組み合わされた schema に対して設定を検証し、状態が独立したスケジューラインスタンスを返します。

:::note 定義を保持し、インスタンスはその都度作成する
ミドルウェアを組み合わせた定義はプログラムレベルで保持します。ユーザーやコレクションの設定が用意できたら `.create({ config })` を呼びます。呼ぶたびに設定を検証して独立したインスタンスを返すため、二つの `.create()` がスケジュール状態を共有することはありません。
:::

## 既製のプリセット

`DefaultScheduler` は非同期ファクトリで、同じ「定義とインスタンス」の仕組みを使い、既定の FSRS-6 モデル・`dateChrono`・標準のスケジュールポリシーを組み合わせてスケジューラを作ります。渡すのはオプションだけです。オプションとバージョンは[DefaultScheduler](./default-scheduler)、最初に動かす場合は[クイックスタート](../quick-start)を参照してください。
