# Reschedule

The `ts-fsrs/reschedule` subpath exposes helpers for replaying or rescheduling reviews against a scheduler while keeping its concrete types:

```ts
import { Reschedule } from 'ts-fsrs/reschedule'
```

`Reschedule<Scheduler>` wraps a scheduler instance and infers the scheduler's card, memory-state, review, and result types from it.

## Replay

`reschedule.replay({ history })` rebuilds the model's memory state from a review history, without touching any card:

```ts
const replay = reschedule.replay({ history })
// replay.memoryState      — memory after the last review
// replay.memoryStates     — memory after each review
```

Each history item is a `{ rating, reviewTime }` pair whose `rating` type is inferred from the scheduler's rating scale (`Rating` for FSRS, or the custom model's rating union). Pass `initialState` in the first argument when continuing from an existing memory state. Both methods accept `{ sortHistory: false }` as their second argument. By default, `sortHistory: true` sorts only when the chronology provides `compare`. With `numericChrono` or a custom chronology without `compare`, input order is preserved, so supply chronological history yourself. Both `replay` and `reschedule` validate every rating with `scheduler.ratings.ratingSchema` (invalid values throw `SRSSchemaError`) and skip entries where `scheduler.ratings.isManual(rating)` is `true`, such as `Rating.Manual` (`0`) on FSRS or a custom manual rating like `-1`. A scale without manual entries skips nothing. At least one non-manual review is required.

If the scheduler type is a union, history can use only ratings accepted by every possible scheduler.

## Reschedule

`reschedule.reschedule({ history, initialCard })` replays the reviews through the scheduler and returns the card and revlog each review produced:

```ts
const result = reschedule.reschedule({ history, initialCard: card })
// result.results  — the card and revlog after each review
// result.card     — the card after the last review
```

`replay` reconstructs stability (`2.3065`) from the history alone; `reschedule` recomputes the card and its due time through the scheduler.

When the model's `forward` returns a packed typed array (for example a `Float64Array` with one fixed-width row per review) instead of an array of states, `memoryStates` is that buffer unchanged and `memoryState` is a `subarray` view of its last row, sharing the same buffer. Build packed models, schedulers and `Reschedule` from the same package (for example all from `ts-fsrs`); mixing packages is not supported.

**Related types** — `RescheduleReview`, `NonManualReview`, `ReplayResult`, `ReplayResultOf`, `RescheduleResult`, and the inference types `CardOf`, `MemoryStateOf`, `MemoryStatesOf`, `TimeOf`, `ScheduleResultOf`.

**See** — [defineScheduler](./define/define-scheduler), [DefaultScheduler](./default-scheduler).

`FSRSMemoryStateSchema` from `ts-fsrs` describes FSRS-3–6 states (`{ stability, difficulty }`). FSRS-7 uses `FSRS7MemoryStateSchema` from `ts-fsrs/models/fsrs-7` and adds `stabilityFast`. Rebuild legacy states by replaying review history with `Reschedule`; migrating weights does not reconstruct the fast trace.
