# DefaultScheduler

`DefaultScheduler` is an async factory that returns a ready scheduler instance. It composes a model (FSRS-6 by default) with `dateChrono` and the standard scheduling policies, so the only thing you configure is its options. Internally it is the same definition-and-instance machinery as a custom `defineScheduler` — the preset is just a convenient assembly.

## Options

| Option | Default | Purpose |
| --- | --- | --- |
| `version` | `'FSRS-6'` | Selects the FSRS model: `'FSRS-3'`, `'FSRS-4'`, `'FSRS-4.5'`, `'FSRS-5'`, or `'FSRS-6'`. The preset migrates parameters for the selected version. |
| `weights` | preset weights | Optional trained weights; omit to use the preset's defaults for the selected version. |
| `desiredRetention` | `0.9` | Target retention applied before interval calculation. |
| `enableShortTerm` | `true` | Enables learning and relearning steps. |
| `learningSteps` | preset steps | Learning steps applied when `enableShortTerm` is on. |
| `relearningSteps` | preset steps | Relearning steps applied when `enableShortTerm` is on. |
| `enableFuzz` | `false` | Spreads intervals for variety when enabled. |
| `maximumInterval` | `36500` | Upper bound on the interval in days. |
| `clearStatsOnForget` | `true` | Whether `forget` clears `reps` and `lapses`. |

`DefaultScheduler` always uses `dateChrono` and composes the standard policies in the order described on the [Middleware](../middleware/built-in) page: desired retention, fuzzing, statistics, scheduled days, learning steps, maximum interval, then monotonic interval. Choosing `version` changes the model and its migrated parameters, not this policy set.

The factory is async, so `await DefaultScheduler(...)` before using the returned instance. The example makes the common defaults explicit: `version`, `desiredRetention`, learning and relearning steps, fuzzing, and `maximumInterval`. Omit `weights` to use the preset for the selected FSRS version.

## Preset or custom definition

Reach for `DefaultScheduler` when the default FSRS model, `dateChrono`, and the standard policy set fit your product — it is the fastest correct start. Reach for `defineScheduler` when you need a different model or chronology, add or remove policies, or expose a configuration you validate per user. Both end in the same scheduler instance API (`newCard`, `review`, `rollback`, `preview`, and `forget`). See [Scheduler overview](./index) for the definition-and-instance model.
