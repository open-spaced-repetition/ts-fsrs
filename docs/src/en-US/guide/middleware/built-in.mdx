# Built-in policies

The following policies are available from `ts-fsrs/middlewares` and the `ts-fsrs` root entry:

| Middleware | Behavior |
| --- | --- |
| `schedulerDesiredRetentionMiddleware` | Applies configured `desiredRetention` before interval calculation for the default FSRS scale. Acceptable values: `(0, 1)`. For custom rating scales, create a matching policy with `createSchedulerDesiredRetentionMiddleware(scale)`. |
| `schedulerLearningStepsMiddleware` | Applies explicit `learningSteps` and `relearningSteps` when `enableShortTerm` is enabled; maintains `learningStep`. Derives step roles from `scheduler.ratings` with no extra options: every lapse grade acts as Again; for non-lapse grades ascending `p1..pn`, `pn` acts as Easy when `n >= 2`, `p(n-1)` (or `p1` when `n = 1`) acts as Good, and the rest act as Hard. Independently of `enableShortTerm`, maps final intervals below `graduatingInterval` (default one day) to `Learning`/`Relearning`, including model intervals. When `enableShortTerm` is enabled and the current state has steps configured, a non-lapse grade without a step uses at least `graduatingInterval`; a grade with a step uses that step, or, with `allowModelOverride`, the model interval when it is longer (for lapse grades, the model interval is capped at `graduatingInterval`). |
| `schedulerFuzzingMiddleware` | Spreads intervals when `enableFuzz` is enabled, using `cardId` and the review count for reproducible results. `createSchedulerFuzzingMiddleware()` accepts custom ranges and RNG. |
| `schedulerMaximumIntervalMiddleware` | Caps the day interval at `maximumInterval`. Explicit learning steps can override this cap as the chain unwinds. |
| `schedulerStatsMiddleware` | Maintains `reps` and `lapses`; `clearStatsOnForget` controls whether forgetting clears them. Counts a lapse whenever `scheduler.ratings.isLapse(grade)` is `true` on a Review card (and undoes it on rollback). |
| `schedulerMonotonicIntervalMiddleware` | Processes all grades in ascending scale order and prevents intervals from decreasing. Once a result of one day or more exists, each later non-lapse candidate of one day or more is at least one day longer than the previous result, and later sub-day candidates keep the previous result. Consecutive lapse grades may tie, as can grades capped at `maximumInterval`. Until a result of one day or more exists, a non-lapse candidate that is no shorter than the previous candidate at second precision, and would land on the same second as the previous result, is moved one second later. Zero-day intervals may tie. |
| `schedulerScheduledDaysMiddleware` | Stores the final interval as nonnegative `scheduledDays` on the card and saves its previous value in the revlog. With the default `fractionalDays: false`, intervals are floored to whole days, so sub-day steps become `0`. With `fractionalDays: true`, fractional intervals such as `0.5` are preserved. |
| `schedulerLeechMiddleware` | Sets `scheduleStatus` to `suspended` on each positive `leechThreshold` multiple of lapses (counted via `scheduler.ratings.isLapse`). The default threshold `0` disables suspension. Your application must respect this status when selecting cards. |
| `schedulerCostAdrMiddleware` | FSRS-only (default scale). Adapts retention to memory state and review cost using `costAdrPolicy` and `goalCostWeight`. When defining a custom scheduler, use it instead of `schedulerDesiredRetentionMiddleware`, not alongside it. |

## Custom scales and `createSchedulerDesiredRetentionMiddleware`

Use `createSchedulerDesiredRetentionMiddleware(scale)` when attaching desired retention to a model with a custom `RatingScale`:

```ts
const myRetentionMiddleware = createSchedulerDesiredRetentionMiddleware(myScale)
```

The `desiredRetention` option of the returned middleware accepts either a single number, which `create()` applies to every grade of `scale`, or a `Record<G, number>` that covers every grade of `scale`. `create()` throws on a missing grade key or a value outside `(0, 1)`; keys that are not grades of `scale`, including manual ratings, are ignored. Scheduler grades outside `scale` keep the scheduler's default retention. `schedulerDesiredRetentionMiddleware` is `createSchedulerDesiredRetentionMiddleware(defaultRatingScale)`.

`DefaultScheduler` already includes the first seven policies. Its order is desired retention → fuzzing → stats → scheduled days → learning steps → maximum interval → monotonic interval. Leech is opt-in when creating your own definition. See [Lifecycle](./lifecycle) for why the order matters and the [Overview](./index) for how middleware runs.
