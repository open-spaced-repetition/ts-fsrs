# State transitions

`State` describes the card's current FSRS learning phase. A card created with `scheduler.newCard()` starts in `New`. On each review, `DefaultScheduler` combines the FSRS model result with the learning-step policy to determine the next state and due time.

![DefaultScheduler state transition flowchart](../../assets/state-transitions.svg)

The diagram and table show the final scheduled interval, after explicit steps and interval middleware. Ratings affect that interval; they do not alone determine the next state.

`graduatingInterval` (default `1` day) is the shortest interval for a card in `Review`. A final interval shorter than `graduatingInterval` enters or keeps `Learning`/`Relearning`; an interval of `graduatingInterval` or longer enters `Review`. This also applies when steps are disabled or empty and the model supplies the interval.

Zero-length steps (such as `0m`, or durations that round to zero seconds) count as no step. Negative durations are not supported.

## What each state means

| State | Meaning | Default queue |
| --- | --- | --- |
| `New` | The card is new or has been reset with `scheduler.forget()`. | `new` |
| `Learning` | The card needs another initial learning review before `graduatingInterval` has passed, from an explicit step or the model. | `learning` |
| `Review` | The card is outside short-term learning; its interval is at least `graduatingInterval`. | `review` |
| `Relearning` | A previously reviewed card needs another review before `graduatingInterval` has passed, from an explicit step or the model. | `learning` |

## How ratings move a card

Ratings first determine whether an explicit step supplies the interval. With `enableShortTerm: true` and at least one step configured, the learning-step policy behaves as follows:

| Rating | `New` / `Learning` / `Relearning` | `Review` |
| --- | --- | --- |
| `Again` | Return to the first step; reset `learningStep` to `0`. | Use the first relearning step; reset `learningStep` to `0`. |
| `Hard` | Keep the current `learningStep`; use the Hard step interval. | Use the model interval, but at least `graduatingInterval`; stay in `Review`. |
| `Good` | Advance when a next step exists; otherwise graduate to `Review` with the model interval, but at least `graduatingInterval`. | Use the model interval, but at least `graduatingInterval`; stay in `Review`. |
| `Easy` | Skip explicit steps and graduate to `Review` with the model interval, but at least `graduatingInterval`. | Use the model interval, but at least `graduatingInterval`; stay in `Review`. |

The Hard step interval is the average of the first two steps, or 1.5 times the only step. With empty steps or `enableShortTerm: false`, every rating uses the model interval, and only the state mapping below applies. `learningStep` keeps the next step only while the card stays in `Learning`/`Relearning`; it resets to `0` when the card enters `Review`.

When `allowModelOverride` is enabled (the FSRS-7 default in `DefaultScheduler`), the scheduler uses the interval from the model instead of the current step if the interval from the model is longer. For Again, the model's interval is capped at `graduatingInterval`, and an Again that uses it always enters `Learning`/`Relearning`. For Hard and Good, a card whose interval reaches `graduatingInterval` graduates to `Review` without finishing the remaining steps. Interval middleware can still adjust model intervals.

**When steps are configured, finishing them or pressing Easy moves the card to `Review`, and a `Review` card rated Hard, Good, or Easy stays in `Review`.**

After the interval is resolved, `schedulerLearningStepsMiddleware` maps it to the next state using the table below. This table describes state mapping, not how each rating selects an interval:

| Current state | Final interval < `graduatingInterval` | Final interval ≥ `graduatingInterval` |
| --- | --- | --- |
| `New` | `Learning` | `Review` |
| `Learning` | `Learning` | `Review` |
| `Review` | `Relearning` | `Review` |
| `Relearning` | `Relearning` | `Review` |

When an explicit step applies, the scheduler keeps its configured duration unless the model from `allowModelOverride` provides a longer interval. A step of `graduatingInterval` or longer still moves the card to `Review`.

:::warning Learning states require the `schedulerLearningStepsMiddleware` middleware
`DefaultScheduler` registers a `schedulerLearningStepsMiddleware` and defaults `enableShortTerm` to `true` including for FSRS-7. For FSRS-7, this flag controls explicit `learningSteps` and `relearningSteps`, not its intrinsic fast trace or the interval-based state mapping. With `enableShortTerm: false`, an interval below `graduatingInterval` still enters the `Learning` or `Relearning` phase.

If you compose with `defineScheduler`, register the middleware with`.use(schedulerLearningStepsMiddleware)` to get this state mapping; without it, the default behaviour remains `Review` with `scheduleStatus: review`, even when FSRS-7 returns an interval below one day. The model computes memory states and intervals; learning-state transitions are middleware behavior. To produce `Learning`/`Relearning` states after FSRS-7 scheduling, register `schedulerLearningStepsMiddleware` or implement your own state-transition middleware.
:::

`Rating.Manual` is not a review grade. Pass one of `Again`, `Hard`, `Good`, or `Easy` to `review()`.

## Run the transitions

The example uses default FSRS-7 with fixed options and disables `allowModelOverride` so each step stays visible. After the explicit learning and relearning steps finish, Good graduates to `Review` for at least one day. Its helper uses the public `DefaultSchedulerCard`, `Grade`, and `State` types directly.

`learningStep` is a zero-based step index, not a review count. The `Hard`, `Again`, and final `Good` examples branch from the same card. If a card is at step `1`: `Hard` would keep its index at `1` (the default Hard interval is `5.5m`), `Again` resets it to `0` (`1m`), and `Good` graduates when there is no next step: the card is scheduled at least `graduatingInterval` later, `learningStep` resets to `0`, and the card enters `Review`. The relearning example shows the same: Again uses the `10m` relearning step, then Good graduates. Intervals are displayed in minutes rounded to two decimals.

:::note dueAt is not now
`dueAt` is when the card becomes due, while `now` is the actual review time and should be equal to or later than `dueAt`. To keep the example deterministic without conflating them, the helper reviews each card 30 seconds after `dueAt`.
:::

## Card, revlog, and memory state

- The input `card` is the state before a review; `review()` does not mutate it.
- `result.card` contains the next `state`, next FSRS memory state (`stability`, `stabilityFast`, and `difficulty` for FSRS-7), and next `dueAt`.
- `result.revlog` records the previous state and memory state together with the selected rating and review timing. That snapshot is also what rollback uses to restore the card.
- `scheduleStatus` controls queue membership. By default it maps `New` to `new`, both learning states to `learning`, and `Review` to `review`; middleware may add statuses such as `suspended` without changing the four FSRS states.

Use `card.state` to find the learning phase, and `card.scheduleStatus` to filter scheduling queues.
