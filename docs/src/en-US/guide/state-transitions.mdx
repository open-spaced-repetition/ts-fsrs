# State transitions

`State` describes the card's current FSRS learning phase. A card created with `scheduler.newCard()` starts in `New`. On each review, `DefaultScheduler` combines the FSRS model result with the learning-step policy to determine the next state and due time.

![DefaultScheduler state transition flowchart](../../assets/state-transitions.svg)

The diagram and table classify the final scheduled interval, after explicit steps and interval middleware. Ratings affect that interval; they do not alone determine the next state.

Zero-length steps (such as `0m`, or durations that round to zero seconds) fall back to the model interval. Negative durations are not supported.

An interval below one day enters or retains `Learning`/`Relearning`; an interval of one day or longer enters `Review`. This also applies when the model supplies the interval because steps are disabled, empty, or completed.

## What each state means

| State | Meaning | Default queue |
| --- | --- | --- |
| `New` | The card is new or has been reset with `scheduler.forget()`. | `new` |
| `Learning` | The card needs another initial learning review within one day, from an explicit step or the model. | `learning` |
| `Review` | The card is outside short-term learning; its interval may come from the model or a step of one day or longer. | `review` |
| `Relearning` | A previously reviewed card needs another review within one day, from an explicit step or the model. | `learning` |

## How ratings move a card

Ratings first determine whether an explicit step supplies the interval. With `enableShortTerm: true` and applicable steps, the learning-step policy behaves as follows:

| Rating | `New` / `Learning` / `Relearning` | `Review` |
| --- | --- | --- |
| `Again` | Return to the first step; reset `learningStep` to `0`. | Use the applicable relearning step; reset `learningStep` to `0`. |
| `Hard` | Keep the current `learningStep`; use the Hard step interval. | Use the model interval. |
| `Good` | Advance only when an applicable next step exists; otherwise use the model interval. | Use the model interval. |
| `Easy` | Skip explicit steps and use the model interval. | Use the model interval. |

The Hard step interval is the average of the first two steps, or 1.5 times the only step. Empty or completed steps, zero-length steps, and `enableShortTerm: false` fall back to the model interval as described above. When no explicit step supplies the interval, the result resets `learningStep` to `0`.

**Easy never advances an explicit step; Good does so only when a next step applies.** Interval middleware can still adjust model intervals. Skipping steps does not guarantee `Review`: with FSRS-7, the resulting interval may still be below one day.

After the interval is resolved, `schedulerLearningStepsMiddleware` maps it to the next state using the table below. This table describes state mapping, not how each rating selects an interval:

| Current state | Final interval < 1 day | Final interval ≥ 1 day |
| --- | --- | --- |
| `New` | `Learning` | `Review` |
| `Learning` | `Learning` | `Review` |
| `Review` | `Relearning` | `Review` |
| `Relearning` | `Relearning` | `Review` |

When an explicit step applies, the scheduler preserves its configured duration. When no step applies, it uses the model interval. Completing a step does not guarantee graduation: FSRS-7 can still return a sub-day interval.

:::warning Learning states require the middleware
`DefaultScheduler` registers `schedulerLearningStepsMiddleware` and defaults `enableShortTerm` to `true`, including for FSRS-7. For FSRS-7, this flag controls explicit `learningSteps` and `relearningSteps`, not its intrinsic fast trace or the interval-based state mapping. With `enableShortTerm: false`, a model interval below one day still enters `Learning` or `Relearning`. When composing with `defineScheduler`, register `.use(schedulerLearningStepsMiddleware)` to get this state mapping; without it, the core review result remains `Review` with `scheduleStatus: review`, even when FSRS-7 returns an interval below one day. The model computes memory state and intervals; learning-state transitions are middleware behavior. To produce `Learning`/`Relearning` states after FSRS-7 scheduling, register `schedulerLearningStepsMiddleware` or implement your own state-transition middleware.
:::

`Rating.Manual` is not a review grade. Pass one of `Again`, `Hard`, `Good`, or `Easy` to `review()`.

## Run the transitions

The example uses default FSRS-7 with fixed options. After the explicit learning and relearning steps finish, the model still returns sub-day intervals, so the cards remain in their learning states. Its helper uses the public `DefaultSchedulerCard`, `Grade`, and `State` types directly.

`learningStep` is a zero-based step index, not a review count. The `Hard`, `Again`, and final `Good` examples branch from the same card at step `1`: `Hard` keeps index `1` (the default Hard interval is `5.5m`), `Again` resets it to `0` (`1m`), and `Good` falls back to the model interval when there is no next step. The result then resets `learningStep` to `0`, but a sub-day model interval keeps the card in `Learning`. The relearning example shows the same distinction. Intervals are displayed in minutes rounded to two decimals.

:::note dueAt is not now
`dueAt` is when the card becomes due, while `now` is the actual review time and should be equal to or later than `dueAt`. To keep the example deterministic without conflating them, the helper reviews each card 30 seconds after `dueAt`.
:::

## Card, revlog, and memory state

- The input `card` is the state before a review; `review()` does not mutate it.
- `result.card` contains the next `state`, next FSRS memory state (`stability`, `stabilityFast`, and `difficulty` for FSRS-7), and next `dueAt`.
- `result.revlog` records the previous state and memory state together with the selected rating and review timing. That snapshot is also what rollback uses to restore the card.
- `scheduleStatus` controls queue membership. By default it maps `New` to `new`, both learning states to `learning`, and `Review` to `review`; middleware may add statuses such as `suspended` without changing the four FSRS states.

Use `card.state` to find the learning phase, and `card.scheduleStatus` to filter scheduling queues.
