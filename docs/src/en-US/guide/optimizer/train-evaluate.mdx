# Train and evaluate

Training runs review history through the binding in a few calls. The input is a review-log CSV; the output is a weight array you can hand to `DefaultScheduler` or a custom `defineScheduler`.

The examples import `@open-spaced-repetition/binding`. In Node that is the native napi module; in a browser it resolves to the WASI Preview 1 wasm build (see the [Optimizer overview](./index) for threading).

## Convert review logs to items

`convertCsvToFsrsItems` reads CSV text and groups rows by card into `FSRSItem`s. The columns are:

| Column | Meaning |
| --- | --- |
| `card_id` | Stable identifier for the card. |
| `review_time` | Review time as epoch milliseconds. |
| `review_rating` | Rating, 1 Again through 4 Easy. |
| `review_duration` | Time spent on the review, in milliseconds. |
| `review_state` | Card state at review time. |

Pass `nextDayStartsAt` (the hour of day the next day begins) and either an IANA timezone such as `'UTC'` or a fixed UTC offset in minutes. For a `Uint8Array` input the call returns items synchronously:

```ts
import { convertCsvToFsrsItems } from '@open-spaced-repetition/binding'

// One card with two reviews: first review today, second the next day.
const csv = [
  'review_time,card_id,review_rating,review_duration,review_state',
  '1704067200000,card-one,3,1000,0',
  '1704153600000,card-one,4,900,2',
].join('\n')

// The day starts at 04:00 local, in the UTC timezone.
const items = convertCsvToFsrsItems(new TextEncoder().encode(csv), 4, 'UTC')

console.log(
  JSON.stringify(
    {
      itemCount: items.length,
      reviewsPerItem: items.map((item) => item.reviews.length),
      ratings: items.map((item) => item.reviews.map((review) => review.rating)),
    },
    null,
    2
  )
)
```

The two reviews for one card become a single `FSRSItem` whose `reviews` hold both rows in chronological order. A card with no later review on another day is dropped, because training needs a retention observation after the initial review.

## Train weights

`computeParameters(items, options)` is asynchronous and returns the trained weights. `enableShortTerm` is required; `numRelearningSteps` and `trainingConfig` are optional, and `progress` reports `(current, total)` while training runs:

```ts
const weights = await computeParameters(items, {
  enableShortTerm: true,
})
```

`trainingConfig` (epochs, batch size, seed, max sequence length, learning rate, and L2 weight) is optional and falls back to the binding's defaults. `computeParameters` runs the real training loop, so call it in a Worker rather than on the main thread. The trainer on the [Playground](../../playground) page runs this same path in a Web Worker and reports progress live. The returned `weights` array is what you pass to `DefaultScheduler({ weights })` or a `defineScheduler` config, replacing the model defaults.

## Evaluate fit

`evaluateWithTimeSeriesSplits(items, options)` splits the review history by time and returns a `ModelEvaluation` with `logLoss` and `rmseBins`, letting you judge whether the trained weights predict held-out reviews. `computeOptimalSteps` goes further: given the reviews and a target retention, it recommends learning and relearning step durations.

See the [Optimizer overview](./index) for the two runtimes and install commands.
