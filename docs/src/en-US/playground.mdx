## Train with the WASIP1 binding

The companion package's browser entry, CSV conversion, `FSRSBindingItem` / `FSRSBindingReview` creation, and every optimizer call stay inside the same dedicated Worker. The main thread only reads the selected `File` as text and sends that text to the Worker.

<RevlogTrainer />

The link downloads a [sample `revlog.csv`](https://github.com/open-spaced-repetition/fsrs-rs/files/15046782/revlog.csv) from `fsrs-rs`: 123,730 review records, 4,626,708 bytes. Parsing uses the binding's Rust `csv` implementation, so quoted fields, embedded commas, and CRLF records are supported. The converter groups rows by `card_id`, sorts each history by `review_time`, and keeps the history beginning at the last New/Learning block. The selected IANA timezone resolves local time and daylight-saving transitions for each timestamp; the selected `nextDayStartsAt` hour assigns earlier local reviews to the previous study day. For FSRS6, the converter derives each `FSRSBindingReview.deltaT` as the whole-day distance between those study dates. Both models create training items only when the current review has `deltaT > 0`.

FSRS7 is the default and uses the same timezone and study-day boundaries. It divides the elapsed time within each study day by that day's actual length and adds the portions across days, preserving fractional and same-day intervals. A complete study day counts as 1 even when DST makes it 23 or 25 hours long. Select the same model for CSV conversion and training.

For FSRS6, enable short-term parameters to model same-day reviews, or turn them off to train long-term-only weights. FSRS7 training always uses `enableShortTerm: true`. Either way the complete returned `weights` array is displayed without rounding or truncation.
