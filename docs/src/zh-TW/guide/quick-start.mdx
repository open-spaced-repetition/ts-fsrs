# 快速開始

## 安裝

`ts-fsrs` 需要 Node.js 24 或更新版本。

<PackageManagerTabs command="install ts-fsrs" />

只有需要訓練 FSRS 參數或轉換複習日誌 CSV 時，才需要另外安裝 `@open-spaced-repetition/binding`。

## 從 DefaultScheduler 開始

`DefaultScheduler()` 是接入 FSRS 排程最快的方式。它預設使用 FSRS-6，並包含目標保留率、統計、學習步驟、最大間隔、單調間隔與已排程天數等標準策略；模糊可透過選項啟用。

```ts twoslash file="../../snippets/run-code/default-scheduler.ts"
```

<RunCode code={defaultSchedulerCode} />

範例明確列出常用預設值。可依產品調整 `desiredRetention`、學習與重新學習步驟、模糊或 `maximumInterval`；省略 `weights` 即使用所選 FSRS 版本的預設權重。

## 建立排程器

需要選擇模型或時間系統，或自行組合 middleware 時，再使用 `defineScheduler`。它會建立可重複使用的 definition；`.create()` 會驗證設定並回傳獨立的排程器。

```ts twoslash file="../../snippets/run-code/define-scheduler.ts"
```

<RunCode code={defineSchedulerCode} />

:::note 重複使用排程器定義
將 `defineScheduler(...)` 的結果（包括透過 `.use(...)` 組合完成的 middleware）保留為程式層級預設。使用者或集合需要排程器時，再呼叫 `schedulerDefinition.create({ config })`；每次呼叫都會驗證該設定並回傳獨立實例。
:::

程式碼區塊的複製按鈕會複製原始程式碼；也可以直接在專用 Worker 中執行。固定的 `now` 讓輸出保持可重現。

- `newCard()` 會建立符合此排程器預設結構的新卡片。
- `review()` 會回傳新的卡片與複習日誌，不會修改輸入卡片。
- 在可重複使用的 definition 上透過 `.use(...)` 組合策略 middleware，再建立使用者專屬的排程器。
