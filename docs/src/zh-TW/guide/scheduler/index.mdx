# 排程器概覽

排程器是你的應用程式用來建立卡片、安排複習的物件。通常不必從頭建置：`defineScheduler({ model, chrono })` 把兩部分組合成可重用的定義，而 `DefaultScheduler` 是基於同一套機制做好的預設。各部分如何組裝見[整體架構](../architecture)；每個元件的詳細說明見[模型](../model)、[Chrono](../chrono) 與[中介軟體](../middleware)。

## 定義與實例

排程器存在於兩個階段：

| 階段 | 是什麼 | 如何取得 |
| --- | --- | --- |
| 定義 | 純 schema 描述：一個模型、一個 chrono，以及選用的中介軟體。不持有設定，也不持有卡片資料。 | `defineScheduler({ model, chrono })` 與 `.use(...)` |
| 實例 | 綁定到一份已驗證設定、可運作的排程器。 | `definition.create({ config })` |

`defineScheduler` 保留具體的模型與 chrono 型別，因此 schema 與處理函式在貫穿 `.use(...)` 時始終有型別檢查。`.use(middlewareA, middlewareB)` 回傳加入這些中介軟體（依序）的新定義；原定義不變，仍可重用。呼叫 `.create({ config })` 會依組合出的 schema 驗證該設定，並回傳狀態獨立、互不共享的排程器實例。

:::note 保留定義，按需建立實例
把包含所組合中介軟體的定義保留在程式層級。當某使用者或集合的設定就緒時再呼叫 `.create({ config })`。每次呼叫都會驗證設定並回傳獨立實例，因此兩次 `.create()` 不會共享排程狀態。
:::

## 現成預設

`DefaultScheduler` 是非同步工廠，用同樣的「定義與實例」機制組裝出預設 FSRS-6 模型、`dateChrono` 與標準排程策略的排程器，你只需傳入選項。選項與版本見[DefaultScheduler](./default-scheduler)；想先跑起來見[快速開始](../quick-start)。
