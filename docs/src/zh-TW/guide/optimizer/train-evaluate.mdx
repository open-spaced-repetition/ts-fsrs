# 訓練與評估

訓練透過幾次 binding 呼叫把複習歷史跑完。輸入是一份複習記錄 CSV；輸出是可直接交給 `DefaultScheduler` 或自訂 `defineScheduler` 的權重陣列。

範例匯入 `@open-spaced-repetition/binding`。在 Node 中是原生 napi 模組；在瀏覽器中解析為 WASI Preview 1 的 wasm 建置（多執行緒說明見[訓練器概覽](./index)）。

## 把複習記錄轉成項

`convertCsvToFsrsItems` 讀取 CSV 文字，並依卡片把各行歸併為 `FSRSItem`。欄位如下：

| 欄位 | 含義 |
| --- | --- |
| `card_id` | 卡片穩定識別碼。 |
| `review_time` | 複習時間，epoch 毫秒。 |
| `review_rating` | 評分，1 Again 到 4 Easy。 |
| `review_duration` | 複習耗時，毫秒。 |
| `review_state` | 複習時的卡片狀態。 |

傳入 `nextDayStartsAt`（新一天開始的小時）以及 IANA 時區（如 `'UTC'`）或固定的 UTC 分鐘偏移。對 `Uint8Array` 輸入，該呼叫同步回傳項：

原本的轉換函式仍回傳陣列。需要一次正規化任意 CSV 卡片識別碼時，使用 `convertCsvToFsrsItemsWithCardIds`：它回傳 `{ items, cardIds }`，串流輸入則回傳 Promise。數值 ID 依本次轉換保留的卡片產生，與排序後的 items 逐項對齊，並非原始識別碼。訓練與直接評估重用同一組 IDs；不要混用不同轉換結果中的 IDs。

CSV 轉換、訓練、評估與排程必須選擇相同的 `modelVersion`（預設 `'FSRS-7'`，也可選 `'FSRS-6'`）。將它作為 `convertCsvToFsrsItems` 的第四個參數，並傳入訓練與評估選項；排程時使用 `DefaultScheduler({ version: modelVersion, weights })`。FSRS-7 產生 34 個權重，依本地學習日的實際時長正規化並保留小數與同日間隔；FSRS-6 產生 21 個權重，使用整數學習日。因此同日的後續複習也能參與 FSRS-7 訓練。

## 訓練權重

`computeParameters(items, options)` 回傳包含訓練權重的 `Promise<number[]>`。`enableShortTerm` 必填；`numRelearningSteps` 與 `trainingConfig` 選填，`progress` 在訓練期間回報 `(current, total)`：

```ts
const weights = await computeParameters(items, {
  modelVersion: 'FSRS-7',
  enableShortTerm: true,
  enableSchedPenalties: true,
})
```

`computeParameters` 和 `evaluateWithTimeSeriesSplits` 在所有建置中都回傳 Promise。原生 binding 透過背景工作執行；兩個 WASI Preview 1 目標（`wasm32-wasip1` 和 `wasm32-wasip1-threads`）都在呼叫執行緒中同步計算，再將結果包裝成 Promise。瀏覽器中應從專用 Worker 呼叫，避免阻塞頁面；Worker 可以在進度回呼中透過 `postMessage` 向頁面傳送進度。

在兩個 WASI p1 目標中，`progress(current, total)` 會在每個訓練 batch 完成後同步呼叫；`evaluateWithTimeSeriesSplits` 則在每個 split 完成後回呼。回傳 `false` 會停止操作並拒絕其 Promise；回呼擲出例外也會拒絕 Promise。資料不足等略過 batch 訓練的情況不會產生訓練進度回呼。`timeout` 是原生進度輪詢間隔，單位為毫秒，並非訓練逾時期限；WASI p1 會忽略它。

`enableSchedPenalties` 選填，預設為 `false`。設為 `true` 會在訓練損失中加入 FSRS-7 的間隔增長和短間隔懲罰。它也適用於 `evaluateWithTimeSeriesSplits` 內部的訓練，FSRS-6 會忽略此選項；它不改變排程公式。

`trainingConfig`（epochs、batch size、seed、最大序列長度、學習率與 L2 權重）選填，缺省時使用 binding 的預設值。瀏覽器中的 WASI 呼叫應在專用 Worker 內執行 `computeParameters`。[Playground](../../playground)頁的訓練器就在 Web Worker 裡執行同一路徑並即時回報進度。回傳的 `weights` 陣列就是傳給 `DefaultScheduler({ version: modelVersion, weights })` 或 `defineScheduler` 設定、用於替換模型預設值的東西。

## 評估擬合

`evaluateWithTimeSeriesSplits(items, options)` 依時間切分複習歷史，回傳 `Promise<ModelEvaluation>`，其結果包含 `logLoss` 與 `rmseBins`，供你判斷訓練權重對留出複習的預測品質。`computeOptimalSteps` 更進一步：給定複習與目標保留率，推薦學習與再學習步驟的時長。
