# 訓練器概覽

FSRS 內建預設模型權重，但你可以用自己產品的複習記錄重新訓練它們，讓間隔更貼合所服務的使用者。訓練器（Optimizer）運行於 `@open-spaced-repetition/binding` 之上：把複習記錄 CSV 轉成訓練項、估算參數，並回報結果對留出複習的預測品質。訓練出的權重透過 `weights` 直接餵回 `DefaultScheduler` 或自訂 `defineScheduler`。權重的含義見[模型](../model)，權重的使用位置見[排程器](../scheduler)。

:::warning 注意
Optimizer 目前仍處於 beta 階段，API 方法可能隨時調整。
:::

## 一個套件，兩種執行環境

原生建置與 WASI 建置提供同一套 API。主套件在 Node 中優先選擇可用的原生模組，瀏覽器入口使用支援執行緒的 WASI 套件。依需求安裝對應套件：

原生模組（Node、伺服器與 CLI）：

<PackageManagerTabs command="install @open-spaced-repetition/binding" />

無執行緒 WASI Preview 1（`wasm32-wasip1`）：

<PackageManagerTabs command="install @open-spaced-repetition/binding-wasm32-wasip1" />

支援執行緒的 WASI Preview 1（`wasm32-wasip1-threads`，發布套件名稱使用 `wasm32-wasi`）：

<PackageManagerTabs command="install @open-spaced-repetition/binding-wasm32-wasi" />

支援執行緒的建置已棄用，本次發布仍保留，預計在下一版本移除。新的 WASI 整合請使用上面的無執行緒套件。

```ts
import { computeParameters } from '@open-spaced-repetition/binding'
```

若要明確選擇無執行緒 WASI，請從 `@open-spaced-repetition/binding-wasm32-wasip1` 匯入。兩個 WASI 套件都可以在 Node 或瀏覽器 Worker 中執行。

:::note COOP/COEP 與多執行緒
無執行緒建置不需要 Cross-Origin-Opener-Policy 或 Cross-Origin-Embedder-Policy 回應標頭。支援執行緒的建置仍要求頁面透過 COOP 與 COEP 回應標頭啟用 `crossOriginIsolated`。執行緒支援描述的是執行環境能力，不代表訓練會自動在背景執行。

`computeParameters` 和 `evaluateWithTimeSeriesSplits` 在所有建置中都回傳 Promise。原生 binding 透過背景工作執行；兩個 WASI Preview 1 目標（`wasm32-wasip1` 和 `wasm32-wasip1-threads`）都在呼叫執行緒中同步計算，再將結果包裝成 Promise。瀏覽器中應從專用 Worker 呼叫，避免阻塞頁面；Worker 可以在進度回呼中透過 `postMessage` 向頁面傳送進度。
:::

## 複習記錄流程

訓練由幾個 binding 呼叫組成一條短流程：

1. `convertCsvToFsrsItems` 把複習記錄 CSV 轉成一組 `FSRSItem`。
2. `computeParameters` 根據這些項訓練權重並回傳權重陣列。
3. `evaluateWithTimeSeriesSplits` 衡量這些參數對留出複習的預測品質。

你還可以用 `computeOptimalSteps` 讓 binding 推薦學習與再學習步驟。逐個呼叫見[訓練與評估](./train-evaluate)；想跑一次真實訓練，用[Playground](../../playground)頁的訓練器。
