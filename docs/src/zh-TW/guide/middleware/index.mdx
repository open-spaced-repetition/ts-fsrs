# 中介軟體概覽

中介軟體為排程器加入排程策略與應用程式所需的欄位。模型計算記憶狀態與間隔，chrono 預設把這些間隔轉換為到期時間；中介軟體位於兩者之間，可以調整目標保留率或間隔、管理學習步驟，以及維護模型未曾見過的額外卡片資料。各部分的職責見[整體架構](../architecture)。

:::note 中介軟體邊界
排程器由模型、chrono 與中介軟體組合而成。讓模型只負責記憶狀態更新與間隔計算，讓 chrono 負責時間值與天數運算；中介軟體在核心操作之前提供輸入、在其後調整結果，並承載這兩者未定義的欄位。
:::

## 定義欄位與行為

`Middleware` 定義包含必填的 `name`，以及選填的 schema、預設值和處理函式。`defineMiddleware()` 根據 schema 推導處理函式中的型別。可以從 `ts-fsrs` 匯入；內建策略也可從 `ts-fsrs/middlewares` 匯入。

| 定義 | 用途 |
| --- | --- |
| `schema.config` | 驗證傳給 `create({ config })` 的設定。中介軟體共用排程器的設定物件。 |
| `schema.card` | 宣告並驗證輸入、輸出卡片上的欄位。 |
| `schema.revlog` | 宣告並驗證複習紀錄欄位，包括復原所需的舊值。 |
| `schema.cardInitInput` | 宣告 `newCard()` 接受的額外輸入，例如卡片 ID。 |
| `defaultValue.card` | 在建立或重設卡片時提供欄位值，透過 `ctx.operation` 區分這兩種操作。 |
| `handlers.review` / `handlers.rollback` | 在呼叫下一個處理函式前後，更新 `ctx.result`。執行方式見[生命週期](./lifecycle)。 |

Schema 同時提供執行時驗證與 TypeScript 型別推導。以下使用實作了 Standard Schema 的 Zod。在自己的應用程式中執行範例時，除了 ts-fsrs 之外還需要安裝它：

計數從 `0` 增加到 `1`，評為 Again 後回到 `0`，復原後還原為 `1`。預覽中，Again、Hard、Good、Easy 對應的計數分別是 `0、2、2、2`，輸入卡片的計數仍為 `1`。

`base.use(streakMiddleware)` 回傳新的排程器定義，原本的 `base` 不變。需要保留回傳值，或像範例一樣接著呼叫 `.create()`。由於中介軟體透過 `use` 組合，處理函式會以固定順序環繞排程器核心——詳見[生命週期](./lifecycle)。

現成的策略涵蓋了常見情境，`DefaultScheduler` 已組合了它們。見[內建策略](./built-in)；直接使用現成排程器見[快速開始](../quick-start)。
